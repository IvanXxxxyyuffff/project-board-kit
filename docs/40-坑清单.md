## 21. 发布「成功」但资产不全

症状：Release 页面只有 zip，没有挂件 exe；或 zip 里只有 `.cs` 没有 `.exe`。
根因：上传返回值当证据、二进制未被 git 跟踪。
解法：`gh_push_gate.py` 现在做两件事：打包后断言必需资产在包内（`必需资产齐全 N/N`），发布后 E13 用 Release API 回读资产清单；缺一即失败。

| 10 | 检索时刷出一大堆压缩过的前端代码 | 在含 vendor/minified 的目录里跑宽泛正则 | 限定 `include` 与目录；复杂检索写脚本落盘再跑，不在命令行拼长正则 |

| 13 | 桌面上出现多个挂件窗口 | 没有单实例保护，且多条启动路径（自启/管道/手动） | 进程级互斥（命名互斥体），非调试模式下重复启动直接退出 |

| 17 | 新增的 CSS 永远不生效 | 产物是「旧 HTML 头 + 新生成体」拼装，样式来自旧头 | 注入块按 id 幂等写入（`<style id="...">`），不依赖生成器是否带样式 |

## 使用方式

- 修 bug 前先查表：症状可能已经有人踩过。
- 修完新坑立刻追加一行（症状/根因/解法三列），不要写在聊天记录里。
- 每条解法要能落成命令或代码改动，否则不算解法。

### 改了 research/ 忘同步套件副本

- 症状：门禁报 `FAIL [副本滞后] research/xxx.py -> 与真源不一致`；或对方拿到的套件跑的仍是旧逻辑。
- 根因：`research/` 是真源，`skills/project-board-kit/files/research/` 是分发副本，改一处没同步另一处。
- 解法：改完先同步副本，再跑 `scripts/release_check.ps1`；按设计不分发的文件放跳过前缀或做占位化。

### 纯数字标题被当噪声丢弃
症状：源系统里明明有待办，看板「我的待办」没有。
根因：合并脚本的噪声判定要求标题含中文，`11111333` 这类编号被过滤。
解法：判定改为「含中文或字母数字即合法」，仅当既无中文也无字母数字才丢弃。

### 未读窗口太短，重启后就空了
症状：挂件刷新后「没有未读消息」，但客户端角标仍显示未读。
根因：未读按「近 3 小时内别人发的文本」筛选，跨小时/重启后归零。
解法：窗口放到 24h，并优先用会话库的未读计数表作为真值。

### 待办不在消息库
症状：翻遍消息库只有「创建了待办」事件、没有标题。
根因：待办存独立的 `forever_store.db`（`todo_v4` 表），消息库只留事件。
解法：单独解密该库（同一把密钥），读 `todo_v4`。
