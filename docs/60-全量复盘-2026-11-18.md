## 4. 发布链体检（治具现状）

`_business\gh_push_gate.py` 一条命令跑完 13 步，顺序即依赖：

1. preflight（9 项卫生；清单哈希落后时自动重建清单并重试一次）
2. gen_manifest → 3. `research/_export_build.py`（占位化 + 覆盖层，重建 `_export/repo`）
4. `scripts/guard_meta.py`（脱敏/清单/占位符/一致性/安装顺序/exe 策略）
5. `scripts/prepublish_gate.py`（E01–E12）
6. 分离部署演练（克隆到 A → 装到 B → doctor 清单必须一致）
7. `git archive` 出 zip + 二进制断言
8. 安装冒烟（zip → 空目录 → setup → doctor）
9. 提交并推送 main
10. Release + 资产上传
11. `cargo build --release --locked` 编译挂件并上传 exe
12. 等 CI（guard-meta）转绿
13. E13 回读 Release 资产

本轮修的两处治具缺陷：

- **推送凭据进 URL**：原来 `https://x-access-token:<token>@github.com/...`，令牌会进进程命令行、失败日志与可能的 `.git/config`。改成 `-c http.https://github.com/.extraheader` 走 header，URL 保持干净，推送后主动 `--unset-all` 兜底，实测 `.git/config` 无残留。
- **代理下大包截断**：补 `http.version=HTTP/1.1`、`lowSpeedLimit=1000/lowSpeedTime=90`，避免 7897 代理的 HTTP/2 early EOF 卡死。
- **预检顺序**：版本号一改，清单哈希必然落后，旧顺序会先判 preflight 失败。改为「失败且原因是清单哈希/清单过期 → 重建清单 → 重试一次」，真实源树脏仍然阻断。
