# 发布前的准备工作（必做清单）

这份清单来自 v2.24.0 的真实事故：仓库发了源码但没发挂件二进制，队友装完拿到的是旧版挂件；离线依赖与 32 位 libcrypto 缺失导致会议与企微链路降级；清单无法重建导致 doctor 永远报「被改过」。

## 一、每次发布前必做的八件事

| # | 检查 | 命令/判据 | 不做会怎样 |
|---|---|---|---|
| 1 | 版本三处一致 | `CHANGELOG` 顶部 = `Cargo.toml` = `config.rs` 的 `APP_VERSION` | 门禁 E06 阻断；用户看不出装了哪版 |
| 2 | 挂件二进制可用且是当前版 | 发布产物里能拿到 `project-board-widget.exe`，`--version` 等于本次版本 | 队友装完是旧挂件（本次事故） |
| 3 | 采集器二进制（仅内部树） | 公开套件不含 cookie 采集器；内部树 `research/em_cookie_scan.exe` 存在 | 会议链路降级为「采集不到」 |
| 4 | 离线依赖随包 | `files/vendor/wheels/*.whl` 含 cryptography/cffi/pycparser；`files/vendor/libcrypto32.dll` 存在 | 新机缺 cryptography、企微库解不开 |
| 5 | 清单可重建且一致 | `scripts/rebuild_manifest.ps1 -Root <root>` 后 doctor 显示「清单一致」 | doctor 永远 FAIL，用户以为装坏了 |
| 6 | 占位符机制存活 | 清单里仍有含 `<ROOT>` 的模板文件；无盘符绝对路径 | 装到别处就崩（路径写死） |
| 7 | 二进制不做文本扫描 | 门禁与导出扫描都跳过 `.whl/.dll/.exe/.png` | wheel 随机字节被误判成敏感词（本次卡点） |
| 8 | 冷启动演练 | 空目录 `git clone --depth 1` → `install.ps1 -Root <空目录>` → doctor | 只有本机能装，队友装不上 |

## 二、一条链跑完（不要手工分步）

```
python _business/gen_manifest.py
python research/_export_build.py
python _business/gh_push_gate.py --version vX.Y.Z --message "feat: ..."
```

`gh_push_gate.py` 内部按顺序做：清单 → 导出 → guard（敏感/占位/副本一致）→ 发布前检查 E01–E13 → 分离部署演练 → 打包 → 推送 → Release → 等 CI 绿。任一步失败立即停。

## 三、发布后必做的三件事

1. 上传预编译挂件二进制作为 Release 资产（`project-board-widget.exe`），并在 Release 说明里写清「如果你没有 Rust 工具链，用这个」。
2. 空目录冷启动复验：`git clone --depth 1` + `install.ps1`，确认 doctor 只剩环境项 FAIL。
3. 记录一条 `CHANGELOG`（改了什么 / 为什么改 / 怎么验证），覆盖层与源码各一份。

## 四、常见事故与对策

- **队友拿到旧挂件**：因为 exe 被打包规则排除或没上传 Release 资产。对策：第 2 项 + 第 8 项。
- **会议链路降级**：采集器缺失或 libcrypto 位数不对（x64 拿不到 32 位库）。对策：第 3、4 项。
- **doctor 一直报「被改过」**：清单按 `<ROOT>` 口径算，安装时被改写。对策：第 5、6 项 + 安装脚本排除 `doctor.ps1`。
- **门禁误报敏感词**：二进制被当文本扫。对策：第 7 项。
- **升级覆盖掉用户配置**：`config.json`/`widget_state.json`/`brief_focus.json` 属「只能合并」。对策：见 `files/_MERGE_POLICY.md`。
