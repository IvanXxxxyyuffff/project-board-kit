## 4. 看板 HTML 的内部结构

页面是单文件、无构建，靠「幂等注入」叠加功能。每个注入块都有固定 id，重复运行只会替换自己：

| id | 来源脚本 | 作用 |
|---|---|---|
| `#st-modal` / `#st-search-fix` | `inject_sheet_truth.py` | 已归档浮层、品牌芯片、搜索覆盖 |
| `#ring-svg-fix2` | `_ring_fix3.py` | 把 CSS `conic-gradient` 甜甜圈重写成 SVG 弧（headless 下 SMIL 不跑，别用 `<animate>`） |
| `#kpi-pop-css` / `#kpi-pop-js` | `_kpi_pop.py` | 01 区「今天必须处理」卡片弹窗 |
| `#gantt-link-css` | `_v4_rebuild.py` | 甘特表头与热力柱联动高亮（`head` 来自现役页，所以样式必须在这里注入） |
| `<script>__DAYCOUNT_SYNC__</script>`（源 `_daycount_sync.js`） | `build_daily_brief.mjs` 内联 | 用 `window.__DAYD` 重算柱高/柱数字/副标，柱=明细行的唯一真值 |

数据岛：
- `window.__DRAW[机型] = {prio,status,stKey,brand,owner,blocker,next,action,note,latest,prog{total,done,pct},ms[{n,p,a,late}],chatMs[],privMs[]}`：卡片/抽屉用。
- `window.__DAYD['YYYY-MM-DD'] = [{model, m, n, ms, dup, plan, actual}]`：14 天热力柱与明细用；按机型平铺一行一个节点，同族同节点第二台起 `dup:true`（空心点）。

## 5. 维护配方

### 5.1 改页面（配色/文案/结构）
1. 只改 `research/build_daily_brief.mjs`（生成器）里的 `CSS` / 模板字符串；不要直接编辑 `项目数据看板.html`（下轮管道会盖）。
2. 若改的是「现役版面」的结构（01/03/04/05 区块 DOM），改完必须让 `_v4_rebuild.py` 重新拼一次 head+body，否则改动只在生成页。
3. 跑 §0 ② 四步，`_page_guard.py` 必须 `GUARD OK`。

### 5.2 加一台机型 / 补节点表
1. 表格侧：确认该机型在 `wxdata/T*_LIVE.txt` 有行网格，`sheet_parse.py` 的机型识别正则 `[A-Za-z]{1,2}\d{3,5}|^\d{4}` 能吃到。
2. 归一：`sheet_canon.py` 的 `brand_group()` 决定品牌归属（客户 A 的两种写法与客户 B 归入各自分组）。
3. 台账：需要人工口径（卡点/下一步/负责人）就写 `research/brief_focus.json`。
4. 重跑 §0 ②，然后 `node_coverage.py` 必须 `hard=0`、`warn` 允许（重名/无节点表属已知）。

### 5.3 加一个看板字段
1. `build_daily_brief.mjs` 里加数据 卡片/抽屉模板里加渲染（`__DRAW` 白名单见 §4）。
2. Rust 侧若要同步显示，改 `rust-widget/src/data.rs`（契约结构体，`#[serde(default)]` 保证旧数据不炸）+ `layout.rs` 绘制。
3. 两处都要改的字段：`tests/` 无，靠 `verify_*.py` 断言兜。

### 5.4 改挂件窗口（尺寸/位置/模式）
- 尺寸常量在 `cmd.rs`（`WIN_W/WIN_H`）与 `layout.rs`（`W/H`）；改一处必须同步另一处，否则命中区会漂。
- 位置/模式在 `widget_state.json` 的 `ui`：`win_mode ∈ {embed,normal,topmost}`（`--mode float` 会回落到 state 里的值）。
- 单实例互斥：`main.rs` 里 `Local\FRD_BOARD_WIDGET_SINGLETON`；`--multi/--selftest/--dump-hit` 不受限（测试用）。

### 5.5 改采集频率
- 挂件：`research/widget_config.json`（`dayMinutes/nightMinutes`，默认 30/60）。
- 定时任务：**日常抓取不依赖 Windows 计划任务** —— 挂件 `项目看板.exe` 开机自启（启动文件夹 `项目看板.lnk`），每 30 分钟跑一次 `每日项目简报.ps1 -PullOnly -NoOpen -NoWidgetRestart`（`rust-widget/src/pull.rs:502`）。Windows 任务 `SELF_CO-Daily-Brief` 由 `research/register_daily_task.ps1` 注册，当前 **Disabled**（Last Run 2026-11-13）：机器不开就没有 09:05 晨报，要启用前先给挂件加「未运行时才跑」的前置判断，否则两层会互相抢锁。DSH 侧 09:10 的「体检 + CLIENT_A 预览」是独立一条 schedule，与抓取无关。

### 5.6 发版到同事机器

## 7. 坑清单（症状 根因 解法）

| 症状 | 根因 | 解法 |
|---|---|---|
| 改完样式没生效，JS 生效 | 页面 `head` 取自现役页，生成器的 CSS 进不去 | 在 `_v4_rebuild.py` 里按 id 注入 `<style>`（参考 `gantt-link-css`） |
| 甜甜圈全灰 | SMIL `<animate>` 在无头浏览器不执行 | 一律用静态 `stroke-dasharray` + GSAP `fromTo` |
| 柱说 5、明细说 7、KPI 说 10 | 三处各读一套聚合 | 只认 `__DAYD` 行数，`_daycount_sync.js` 统一重算 |
| 部署后行为没变 | `Copy-Item` 被运行中进程占用、静默失败 | `Stop-Process` 等 800ms 复制 `Get-FileHash` 比对 |
| `cargo build` 报 `failed to remove … exe 拒绝访问` | 有旧进程直接从 `target\release\` 跑 | `Get-Process | Where Path -like '*rust-widget\target*'` 杀掉再编 |
| `RUSTFLAGS='-C linker=rust-lld.exe'` 编译失败 | 会让 build script 崩 | rust-widget 是 ASCII 路径，不加 RUSTFLAGS；只有 `wxread` 中文路径需要 |
| PostMessage 点击自绘窗口无反应 | 自绘窗口不走标准路由 | 用 `--dump-hit` 导命中区 / 真实输入；日志不落即未命中 |
| PowerShell here-string 吞中文/反斜杠 | PS 解析引号与转义 | 补丁脚本一律 `write` 成 `.py` 落盘再跑 |
| `view.rs` 补丁断言失败 | 文件是 CRLF，锚点用 `\n` | `raw.replace('\r\n','\n')` 打补丁后还原 |
| pwsh 输出「path too long」 | 巨幅源码经工具回传溢出，不是脚本失败 | 看落盘文件/日志判断成败 |
| `edit` 工具匹配 Rust 行失败 | 显示层会翻倍反斜杠 | 大段改动用 `write`+python 按行 splice |
| 设置面板改完保存不生效 | 字段被 `serde(default)` 静默丢弃 | 新字段必须同时加到 `Config` 与 `from_args()` |
| 桌面出现多个挂件 | 旧 exe 从 target 直跑 + 自启叠加 | 单实例互斥已加；查 `Get-Process 项目看板` 与 `Path` |

## 一致性保障（PARITY）

`scripts/guard_meta.py` 的 `PARITY_GROUPS` 做逐字节比对（去 BOM、CRLF 归一后算 sha256）：

| 组 | 真源 | 副本 |
|---|---|---|
| 挂件源码 | `rust-widget/src/*.rs` | `skills/project-board-kit/files/rust-widget/src/*.rs` |
| 挂件清单 | `rust-widget/{Cargo.toml,Cargo.lock,build.rs,README.md}` | 同名副本 |
| 采集/解析/看板脚本 | `research/`（递归；跳过 `raw/ wxdata/ api/` 等） | `skills/project-board-kit/files/research/` |

- 失败形如 `FAIL [副本滞后] research/xxx.py -> 与真源不一致`：按提示同步副本，不要改门禁。
- 按设计不分发的脚本（含本机路径/真实台账）要么放跳过前缀，要么在分发前占位化：不要靠「记得别提交」。
- PARITY 只能发现「两边不一样」，发现不了「两边都错」；后者靠治具（见 `docs/20-检测治具.md`）。

## 二十一、企业微信本地数据（只读、零中断）

企业微信 5.x 的 `message.db / session.db / user.db` 是 wxSQLite3（SQLite3MultipleCiphers）AES-128-CBC 加密，密钥是 16 字节原始 key，只存在于客户端进程内存里。

**硬约束（必须遵守）**：不注入、不写目标进程内存、不重启客户端、不调登录接口。写入 9 字节补丁的方式会让多线程撞半指令导致客户端崩溃，实测连崩三次，已废弃并从仓库移除。

三步链路：

1. 取密钥：`research\wxwork_enable.ps1`（内部调 `wxwork_key_readonly.exe`）只读扫描客户端内存，用页 1 的 `SQLite format 3` 头做校验，命中即返回 32 位 hex。
2. 解库：脚本把 `session/message/user.db` 复制到 `research\_wxdec\` 后用 `wxwork_db_decrypt.py` 离线解密，客户端持锁不受影响。
3. 校验：解密后跑 `wxwork_chat_export.py`，打印 `CHAT OK convs=.. group=.. direct=.. msgs=..` 即通过。

排错表：

| 现象 | 原因 | 处理 |
|---|---|---|
| `KEY_NOT_FOUND` | 客户端空闲时密钥不在内存 | 在企微点开任意会话后重跑 |
| `LIBCRYPTO_MISSING` | 缺少 32 位 openssl | 从企微安装目录复制 `libcrypto-1_1.dll` 为 `research\libcrypto32.dll` |
| `decrypt FAIL` | 换了账号或大版本导致密钥变化 | 删 `_wxdec\_key.txt` 后重跑（自动重新扫描） |
| `WXWORK_DB_MISSING` | 未登录或未产生数据 | 先登录客户端 |

**已知边界**：企业微信「待办」不落本地库（无 todo 表、`content_type=675` 只有「创建了待办」事件、CEF 存储 8 MB 全量检索无「待办/todoId」），它走 CRTX 私有二进制 RPC，只读前提拿不到；需要待办时走 E-Mobile 审批待办或本机手工待办。

## 二十二、企业微信操作红线（2026-11-17 事故后新增）

**只允许**：复制数据库文件离线解密、只读进程内存（ReadProcessMemory）、复用已登录 cookie 查询。

**禁止**（任一条都可能触发设备安全验证或直接掉线）：
1. 向企微发送任何输入事件（鼠标点击、按键、SendInput/mouse_event/PostMessage 键盘）
2. 结束、重启、kill 企微进程
3. 调用登录/验证类接口，或替用户完成扫码
4. 注入、写内存、改代码段（9 字节非原子补丁曾致连崩三次）

事故记录：2026-11-17 22:18 用自写点击器点左侧「待办」，进程换 pid 并弹「设备环境异常需扫码验证」；
22:26 为恢复而重启进程，会话被清空，退成扫码登录。**结论：客户端一旦弹验证，只能由用户手机扫码，任何自动恢复都会加重风控。**

待办取数改用被动方式：`research/wxwork_todo_capture.py`（只读内存标记扫描，零输入事件）。
### 每日管道的企微/会议步骤（5a4–5a7）

| 步骤 | 脚本 | 产出 | 失败时 |
|---|---|---|---|
| 5a4 会议安排数据 | `research/ec_meeting_fetch.py` | `research/meeting_data.json` | 降级，看板保留上次数据 |
| 5a5 企微未读+三源交叉验证 | `wxwork_unread_build.py` + `wx_crosscheck.py` | `wxwork_unread.json` / `wx_crosscheck.json` | 降级，未读区显示空 |
| 5a6 企微日历并入会议 | `wxwork_calendar.py` + `wxwork_calendar_merge.py` | 合并进 `meeting_data.json`（标题带〔日历〕） | 空日历视为正常（退出 0） |
| 5a7 企微待办并入部门进度 | `wxwork_todo_merge.py` | 写 `widget_state.json` 部门待办 | 无取证文件时只打印 SKIP |

这四步都只做只读操作：cookie 来自客户端内存、日历/消息库是文件副本离线解密、待办是只读内存取证。任何一步都不发输入事件、不重启客户端。

## 二十三、企业微信待办（只读导出，零注入）

待办不在 `message.db`，而在 `Documents\WXWork\<账号>\Data\forever_store.db` 的
`todo_v4` 表（列 `id / content / status / create_time / update_time / remind_timestamp`）。
该库与 `message.db` 用同一把 wxSQLite3 密钥，可离线解密，不需要登录态、不需要点击客户端。

| 步骤 | 脚本 | 产出 | 失败表现 |
|---|---|---|---|
| 解密待办库 | `research/wxwork_todo_local.py --days 180` | `research/wxwork_todo.json` | `TODO_LOCAL fail reason=no_key/decrypt` |
| 并入部门待办 | `research/wxwork_todo_merge.py` | `widget_state.json` 的 `department` | `MERGE_WX items=0` |
| 挂件显示 | 重启挂件 | 「部门进度」我的待办 | 无 |

约定：
- `status=4` 视为已完成/已关闭，不导出；其余视为未完成。
- 纯数字/字母标题（机型号、编号）是合法待办，不要按噪声丢弃。
- 待办合并必须在挂件停止时执行，否则内存态会覆盖磁盘。
