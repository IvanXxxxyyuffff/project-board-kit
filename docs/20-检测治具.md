# 检测治具（Verification Fixtures）怎么建

> 目的：让「改完到底对不对」这件事可自动判定，而不是靠人眼截图。
> 本文只讲方法与流程，不含任何具体业务值、路径或阈值样例的私有内容。

---

## 1. 分三层，不要混

| 层 | 判什么 | 特点 | 失败时 |
|---|---|---|---|
| L1 数据层 | 输入源 中间产物 页面数据岛，数值与结构是否自洽 | 纯读文件/读 HTML，秒级 | 直接红，阻断发布 |
| L2 运行态层 | 真浏览器渲染后，DOM 是否与数据一致、交互是否生效 | 需要无头浏览器，十秒级 | 直接红，阻断发布 |
| L3 体验层 | 观感、间距、动效、可读性 | 人工/截图对比 | 只记录，不阻断 |

原则：能用 L1 判的，绝不下放到 L2；L3 永不进 CI 的硬门。

---

## 2. 建治具的标准流程

1. 先写失败用例：拿一次真实故障（用户报的 bug 就是最好的用例），先写一条会红的断言，跑一遍确认它真的红。
2. 再修代码：修到断言转绿；不修断言。
3. 补负例：故意构造「坏输入」（空表、缺列、重复行、跨天）验证断言真的会红：只测绿不测红的治具等于没有。
4. 固化成命令：一条命令跑完一层，退出码非零即失败，便于接入管道与定时任务。
5. 接进主管道：作为管道中的一步（`Add-Step` 命名要能看出查什么），失败要能让这一步红。

---

## 3. 断言该写什么（按类别，不按数量堆）

L1 常见类别
- 总量守恒：明细条数之和 == 汇总条数（防止只改一半）。
- 口径一致：同一数字在「卡片 / 柱状值 / 明细头 / KPI」四处必须相等。
- 时间语义：所有「未来/逾期/待办」都从日期字段现算，不允许读预生成的字符串。
- 唯一性：同一实体在同一天不得重复计数（去重键要写清：实体 + 日期 + 节点）。
- 字段完备：必填字段非空率、枚举值是否在允许集合内。
- 外键对齐：页面里的每个实体，必须在数据源里存在（防止幽灵条目）。
- 幂等：同一输入跑两次，产物字节一致（或只有时间戳不同）。

L2 常见类别
- 结构存在：关键区块、数据岛、注入脚本 id 都在。
- 交互生效：点击后状态类名/可见性真的变化，且互斥项被清掉（高频 bug）。
- 无运行期异常：监听 `pageerror`，出现即红。
- 顺序正确：用 `compareDocumentPosition` 判相邻/前后，不要用 `getBoundingClientRect().top`（隐藏节点会误判）。
- 隐藏元素要绕开：被浮层盖住/不可见时，用脚本触发点击而不是模拟坐标点击。

负例（必须有）
- 空数据 应显示空态而不是崩或显示 0 条却报有数。
- 缺列 应回退到默认列或跳过，而不是整表解析失败。
- 重复输入 合计不应翻倍。

---

## 4. 目录与命名约定

```
research/verify_<layer>.py         # L1 静态/数据断言
research/verify_<layer>.mjs        # L2 运行态断言（无头浏览器）
research/_page_guard.py            # 产物结构自检（可自愈）
research/node_coverage.py          # 跨源交叉验证（只读）
```

- 断言函数返回 `(ok, msg)` 列表，最后统一打印 `PASS/FAIL` 计数与首条失败信息。
- 退出码：`0` 全绿；`1` 有硬失败；`2` 环境缺失（浏览器/端口未起）。
- 每条断言写「失败了意味着用户会看到什么」，而不是复述代码。

---

## 5. 与其他环节的关系

- 管道：`verify 生成 guard 覆盖交叉验证`，任一步红则该轮标记降级。
- 定时任务：每天首次运行先跑 L1+L2，红了先自修（重生成/重注入）再复跑，仍红才报人。
- 交接：新接手的人只要跑治具，就知道「系统现在是不是好的」，不必读全部代码。

---

## 6. 反模式（踩过的）

1. 用「页面体积 > N KB」当唯一断言：版面变了照样绿。
2. 拿截图当断言：无法在 CI 判定，且像素抖动就红。
3. 断言写死业务数字：数据一变就红，最后被注释掉。
4. 只测正常路径：真正的 bug 都在空值/重复/跨天。
5. 治具自己崩了当绿：必须区分「断言失败」与「治具异常」，后者要红。

## 发布前检查（`scripts/prepublish_gate.py`）

一条命令把「推上去才发现的问题」前置。检查对象是将要发布的那棵树，不是开发工作树。

```bash
python -X utf8 scripts/prepublish_gate.py --version vX.Y
python -X utf8 scripts/prepublish_gate.py --selftest --version vX.Y   # 自检治具覆盖度
```

| 编号 | 检查 | 抓什么 |
|---|---|---|
| E01 | 内建门禁 | 调 `scripts/guard_meta.py`，脱敏/清单/占位符/一致性/安装顺序/exe 策略全绿 |
| E02 | 真实业务词 | 词表不在仓库里（`PREPUB_LEAK_FILE` 指定），命中即失败 |
| E03 | 本机绝对路径 | 盘符路径、用户目录、临时目录 |
| E04 | 清单可还原 | 声明↔实体双向、字节数、sha256、`<ROOT>` 占位符存活 |
| E05 | 文档齐全 | 必备文件 + 无重复章节标题（历史事故：README 出现两个「5.」） |
| E06 | 版本一致 | CHANGELOG 顶部 ↔ 发布参数 |
| E07 | 安装链可执行 | `setup discover doctor` 顺序、`doctor` 用拼接还原 `<ROOT>`、（内部树）`em_cookie_scan` 编译步骤、ps1 的 UTF-8 BOM |
| E08 | 残留物 | 日志/备份/演练目录/`__pycache__`/裸 `out.txt` |
| E09 | 体积与二进制 | >5 MB 文件、未在白名单的二进制 |
| E10 | 文档与代码 | Markdown 里引用的脚本必须存在（未随仓库分发的模块前缀除外） |
| E11 | 文档风格 | 禁止 emoji、禁止用「：」代替标点、禁止整行加粗当小标题 |
| E12 | C# 采集器可编译 | 导出仓里每个 `.cs` 都用 `csc` 真编译一遍；脱敏若改动代码字面量（如把长度常量换成占位符）会在这里红 |
| E13 | Python 依赖完整 | 导出仓里每个 `.py` 的 import 都能在树里解析（`try/except` 包裹的可选依赖除外）；历史事故：解密器按取证工具 drop 掉，两个脚本仍 `import wxwork_db_decrypt`，装完直接 ImportError |

为什么要自检：治具会骗人：之前 `PARITY` 只比对 27 个文件，范围外的漂移照样 PASS。
`--selftest` 会复制一份干净树、逐项注入违规（塞真实词、塞盘符路径、改清单字节数、造重复标题、
改版本号、造副本漂移、写反安装顺序、塞日志、塞二进制、引用不存在的脚本），
断言对应检查确实变红；漏报即 `SELFTEST_RESULT=FAIL`。

公开仓 CI 也跑这套检查，但 CI 里没有私有词表（词表按设计只放发布机），
因此 CI 用 `PREPUB_ALLOW_NO_WORDS=1` 显式跳过 E02；业务词零命中的硬断言只在本机
`gh_push_gate.py` 里执行（它会把 `PREPUB_LEAK_FILE` 传给检查器）。CI 绿不等于 E02 通过。

## 秘密扫描（`scripts/secret_scan.py`，CI 常驻）

E02 靠私有词表，覆盖「业务名 / 客户名 / SKU / 内网主机」；`secret_scan.py` 靠**通用模式**，
覆盖「凭据形态」。两者的模式都公开、不需要词表，所以这一层可以直接挂在公开仓 CI 上。

| 类别 | 规则 | 抓什么 |
|---|---|---|
| 厂商令牌 | `github-token` `github-pat` `aws-key` `slack-token` `google-key` | `ghp_`/`github_pat_`/`AKIA`/`xox[baprs]-`/`AIza` |
| 私钥 | `private-key` `jwt` | `-----BEGIN … PRIVATE KEY-----`、三段式 JWT |
| 本工程凭据 | `wecom-cookie` `cookie-assign` `auth-header` | `wedoc_sid`/`wedoc_skey`/`tdoc_uid` 等 cookie 名带赋值、长 cookie 串、`Authorization: Basic/Bearer` 实体值 |
| 内网 | `private-ipv4` `weaver-host` | `10.x` / `192.168.x` / `172.16-31.x`、`*.weaver.com.cn` 主机 |
| 本机痕迹 | `win-user-path` `drive-path` | `<ROOT>\<名>`、`D:` 下专有目录名 |
| 个人数据 | `email` `cn-mobile` | 邮箱、大陆手机号（两侧贴字母数字不算，避免 sha256 误报） |

误报处理：整行是哈希 / `"sha256": "…"` 字段直接跳过；`127.0.0.1`、`localhost`、`<占位符>`、
`example.com`、`xxx` 一类示例值放行。改动规则后必须跑两边验证：

```bash
python -X utf8 scripts/secret_scan.py --root .            # 业务树：应当有命中（证明规则会亮）
python -X utf8 scripts/secret_scan.py --root _export/repo # 导出树：必须 PASS
```

通过判据：`SECRET_SCAN_RESULT=PASS files=N`。

## GitHub 侧安全项（免费 vs 付费，2026-11-20 实测）

| 项 | 状态 | 说明 |
|---|---|---|
| `secret_scanning` | 免费公开仓默认开 | 扫厂商格式 |
| `secret_scanning_push_protection` | 免费公开仓默认开 | 含秘密的 push 服务端拦截 |
| `dependabot_security_updates` | 手动开可行 | 依赖漏洞自动开修复 PR |
| `secret_scanning_non_provider_patterns` | **付费 Secret Protection** | API 返回 200 但值被忽略，回读仍是 `disabled` |
| `secret_scanning_validity_checks` | **付费 Secret Protection** | 同上 |

教训：这类开关**必须回读 `security_and_analysis` 的值**才判断是否生效，看 HTTP 200 会误判成已开。
付费项开不了的缺口，由 `secret_scan.py` + E02 两层补上。

通过判据：`PREPUBLISH_RESULT=PASS checks=13 failed=0` 且（发布时）`SELFTEST_RESULT=PASS blind=0`。
